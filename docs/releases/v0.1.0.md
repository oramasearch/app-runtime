# app-runtime v0.1.0

2026-10-26. The first release of the Python base runtime that runs lake Apps. Image: `oramasearch/app-runtime:v0.1.0`
(private). Every Lake runs Apps on it, through the operator's apps runtime image.

## What it includes

Everything in the runtime, as of this release:

- **Loading an App** ([Loading an App](../loading/apps.md)):
  - The source comes from `APP_SOURCE=<lake_url>|<repository>|<revision>|<path>`, or `LAKE_URL`, `APP_REPOSITORY`,
    `APP_REVISION` and `APP_PATH`, with the read-only bearer token in `APP_TOKEN`.
  - The pinned tree is read through lake's `repository_tree` and `repository_file` and written below `/tmp`.
  - `app.toml` (`name`, `framework`, `entrypoint`, `port`, `dependencies`, `bindings`) is validated without installing
    anything.
  - A declared dependency is accepted when it is installed and satisfies its specifier; URL requirements are always
    refused (#6).
  - An App baked into the image loads too (#8).
- **Frameworks** ([Frameworks and health](../runtime/frameworks.md)):
  - FastAPI (`module:object`), whose lifespan runs inside the runtime (#10).
  - Streamlit (a Python script) on loopback, behind the runtime's proxy for HTTP and WebSocket.
  - Static (a content directory with HTML index support).
  - `/healthz` and `/readyz` on the public port for every framework; `APP_PORT` overrides the manifest port (default
    8080).
  - The App root stays on Python's module path for handler-time imports.
- **Streamlit stream fix** (#17, issue #16):
  - The runtime relays Streamlit's WebSocket only when its `Origin` names the host it was sent to, and gives Streamlit
    its own loopback origin.
  - Streamlit starts with `--browser.serverAddress=127.0.0.1`.
  - Before this, a Streamlit App behind its public host answered 500. Streamlit made a blocking external IP lookup that
    a pod without internet egress waits on, and then refused the stream (403).
- **Bindings and data Apps** ([`orama_app` and bindings](../data-apps/bindings.md)):
  - Binding JSON at `/var/run/orama/bindings/zetta` and `/var/run/orama/bindings/services/<name>`, parsed in the
    operator's exact Zetta binding shape (#15, lake#1205).
  - The `orama_app` package: `zetta()` for governed workspace SQL, datasets, runs, models and scoring; `service(name)`
    for a Service's connection fields; request-local `current_user()` for `auth: lake` (bare user id accepted, #4).
- **Image:** Python 3.12, UID 10001, App code below `/tmp` (works with a read-only root filesystem), the pinned baked
  set (FastAPI, Uvicorn, Streamlit, pandas, NumPy, Plotly, HTTPX, Pydantic, Jinja).
- **Example:** [`examples/data-dashboard`](../../examples/data-dashboard/), a Streamlit App over a fakeable Zetta
  binding.

## Not included

- No framework other than FastAPI, Streamlit and static.
- No installing of dependencies at startup: Apps that need more use image mode (lake's `build_app`).

## Known issues (security first)

- **[#13](https://github.com/oramasearch/app-runtime/issues/13) (LSR-182, low):** on a **Public** App, the runtime
  reads identity headers (`X-Orama-User` and the like) that the client supplied. A Public App's ingress does not
  overwrite them, so `current_user()` can name someone who did not sign in. The fix also needs the operator. Until then,
  only `auth: lake` Apps can rely on `current_user()`.
- [#12](https://github.com/oramasearch/app-runtime/issues/12): the pre-launch security review's other findings for the
  runtime.

## Where it has run

Nowhere: v0.1.1 replaced it the same day, before any roll. Until then every Lake ran `oramasearch/app-runtime:976e6a8`.
